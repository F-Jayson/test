# NotePad 期中实验项目规划

用户可以在列表查看最后修改时间，按标题或正文找到笔记，切换编辑器纸张，并将一条笔记导出成文本。整本备份和恢复由用户在 NotePad 内手动发起，通过 WebDAV 与云盘交换数据。

实验说明《期中实验_NotePad记事本应用.pdf》第 2 页规定两项基础功能并列出扩展示例，第 3 至 5 页给出参考界面。本项目自选的第一组扩展是 UI 美化，包括列表主题、纸张背景与编辑器。第二组是笔记导出、云备份与恢复。

## 云备份的演示方式

按用户选定的方案二，应用通过 HTTPS 访问支持 WebDAV 的云盘。默认以坚果云举例。演示者在坚果云建一个可写的 `NotePad` 文件夹，通过“账户信息 → 安全选项 → 第三方应用管理”生成专用应用密码。NotePad 接收目录地址、账号和应用密码，示例目录地址为 `https://dav.jianguoyun.com/dav/NotePad/`。其他兼容服务可填写自己的目录地址，兼容性以实际验证为准。[坚果云第三方授权说明](https://help.jianguoyun.com/?p=2064) · [坚果云目录地址示例](https://help.jianguoyun.com/?p=3234)

为控制实现规模，远端只维护一个 `notepad-backup.json`。用户点击“备份”将当前整本快照上传，界面说明再次备份会替换旧副本。点击“恢复”从同一路径下载，确认后补回本地缺失笔记。TXT 导出继续使用系统文件选择器。真实云端验收需要服务端成功响应、从云盘查看文件，以及应用重新下载后的数据比对。

## 任务明细与验收

### T01 · 留下原版对照

1. 顺着现有新增、保存、列表查询、改标题路径读源码，记下关键类、时间写入点、原菜单与纯文本能力。
2. 在独立实验设备或模拟器准备两条之后还能复用的笔记，走通新增、重开、编辑、改标题、撤销，另用一条临时笔记验证删除。记录原版设备/API 和基线测试情况。
3. 验收材料为原版列表、编辑器的真实截图，以及哪些现象源于运行、哪些仅从源码确认的简表。后续任务可直接引用这组原图。

### T02 · 让时间戳能说明笔记最后何时改动

1. 在列表投影和适配器中加入 `modified`，标题下显示本地日期及时间。保留 ID 和标题原有用途，历史缺失时间的行显示占位。
2. 正文保存和改标题入口都比较实际内容。发生变动时更新修改时间。沿用原创建时间和已有倒序。分别检查只看就返回、撤销编辑和新建空笔记退出。
3. 验收时先记录两条已存笔记，再改较早的一条，核对时间和首行变化。只改标题也应更新时间。保留前后图。同一分钟内的细小变化可核对底层毫秒值。

### T03 · 一个输入框同时查标题和正文

1. 在列表增加搜索入口，按标题或正文包含输入文字筛选。复用带参数的 Provider 查询。单引号、百分号、下划线按用户输入的普通字符处理。
2. 清空恢复全量列表，无匹配时给出反馈。切换结果时管理旧游标。返回列表时按现有搜索条件刷新。保留时间排序、点击和长按入口。
3. 用一个关键词构造“只在标题命中”“只在正文命中”“完全不命中”三条样本。核对返回集合、清空结果、编辑后不再命中、过滤后点开或长按的笔记 ID。截图配上关键词和命中原因。

### T04 · 明确列表层级并统一界面主题

1. 设定一套简洁浅色主题，在资源中统一文字、颜色和间距。协调列表、操作栏和标题编辑弹窗，保留已有菜单入口。
2. 调整标题与时间的字号、对比和留白。区分“还没有笔记”和“没有匹配的笔记”。检查长标题、较大字号、状态栏与输入区域的可见性。
3. 在尽可能相同的数据和设备上对照 T01，展示完整列表和搜索空状态。实测点击、长按与新建仍可用。报告中可用前后图说明具体改进。

### T05 · 优化编辑器并允许更换纸张

1. 基于 `LinedEditText` 调整正文字号、行距、内边距和横线颜色，用多行中文检验阅读和键盘输入。
2. 提供“白纸／暖纸”两种背景，编辑器菜单直接切换，一个全局偏好保存选择。当前输入、光标与滚动应尽量保持，重开后沿用上次选择。
3. 验收用同一篇正文截取两种背景。补测键盘展开、长文滚动、保存重开，以及仅改外观不会推进这条笔记的修改时间。

### T06 · 把选中的一条笔记导出成 TXT

1. 从列表长按进入“导出为文本”，绑定所选笔记 URI，复用 Provider 的 UTF-8 输出。用系统创建文档功能让用户决定保存位置和文件名。
2. 从源 URI 复制到目标 URI，读写安排在后台。处理返回、取消、写入失败和同名标题。以实际写入完成为成功条件。
3. 选取含中文、多行的样例，用另一款文本查看器打开成品核对标题、空行、正文，再验证取消后源笔记完好。同名不同正文可用来检验导出对象是否正确。

### T07 · 确定整本笔记的备份格式

1. 独立查询笔记集合 URI，读取全部笔记。以 UTF-8 JSON 保存顶层整数 `version`（初版为 1）和 `notes` 数组。每条记录包含 `title`、`note`、`created`、`modified`，时间为原始整数毫秒，空库对应空数组。本地 ID 与纸张偏好留在本机。
2. 用一个小型读写实现完成编码、解码及必要的格式校验。保留正文中的中文、换行、引号和空字符串，拒绝损坏 JSON、未知版本或字段类型有误的文件。
3. 用同一批数据做“读出 → 编码 → 解码 → 逐字段对照”，记录样本和结果。T08 和 T09 共用这份实现。此任务的证据是数据对照和测试结果。

### T08 · 在 NotePad 中手动备份到 WebDAV

1. 列表提供“云备份与恢复”入口。用一个小界面填写已有的 HTTPS 目录、账号和应用密码。目录与账号可记住，应用密码采用掩码输入，仅用于当前会话。Manifest 声明网络权限，网络读写放后台并设置连接、读取超时。
2. 点击备份，说明条数和替换旧远端快照的效果，确认后通过 HTTPS `PUT` 上传 T07 生成的 JSON。空库也要明确提示本次为 0 条。只在服务确认写入后显示成功和条数，区分凭据错误、目录不可用及网络失败。
3. 在实验专用云目录验证首次上传、更新快照和取消，从筛选列表发起也应上传全部。通过坚果云网页端或其他客户端核对文件与内容，记录可观察的条数和样例。缺少可用账号时先验证可独立测试的部分，保留真实云端待验项。

### T09 · 从 WebDAV 恢复缺失的笔记

1. 在同一界面点击恢复，从已配置目录用 HTTPS `GET` 下载固定文件，复用 T07 校验版本、数组、字段类型与时间值。展示备份条数和“保留本地、补入缺项”的规则，请用户确认后再写库。
2. 一次事务内完成比较和插入。按标题、正文、创建及修改毫秒值四项完全一致判断已存在。遇到完全相同的多条记录按数量补齐。保留本地额外笔记、同名不同正文和原始时间，让 Provider 分配本地 ID。重复导入同一备份后新增应为零。
3. 从云端下载 T08 的真实备份到含一条本地独有笔记的实验环境。核对数量、正文、时间和排序，再次恢复。另测取消、远端无文件、网络中断、无效备份、空备份及写入中断。失败后核对本地仍完整。用恢复前后列表与一条恢复笔记的详情作为证据。

### T10 · 串起演示流程并核对报告材料

1. 在同一套演示数据上串联新增、改标题或正文、查看时间排序、按正文搜索、切换纸张、导出 TXT、云端备份和恢复。回归原有撤销、复制／粘贴及删除入口。
2. 在可用设备运行已有测试和新增的针对性测试。把自动化结果、界面实测、真实云端往返分别登记。云端往返需有外部客户端可见、NotePad 通过 WebDAV 重新取回副本、恢复结果一致的证据。
3. 在 T10 记录中用“报告章节／任务实现／测试证据／截图”表链接已有材料，补上能实测的缺口。某项受阻时列出实际原因与剩余验收动作，保持对应任务的真实状态。
