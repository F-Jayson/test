## 起点与实现

[T01](T01-原版基线.md) 实测发现，原版只看正文就返回也会更新时间，只改标题却不更新。SQLite 已有毫秒字段 `created` 和 `modified`，Provider 插入时补齐未传的时间，默认按 `modified DESC` 排序。因此本次继续使用原表、原 URI 和原排序，读取历史时间直接展示。 [数据契约](../../app/src/main/java/com/example/android/notepad/NotePad.java) · [Provider](../../app/src/main/java/com/example/android/notepad/NotePadProvider.java)

| 文件与入口 | 本次实现 |
| --- | --- |
| [NotesList.onCreate](../../app/src/main/java/com/example/android/notepad/NotesList.java) · [列表行布局](../../app/src/main/res/layout/noteslist_item.xml) · [字符串资源](../../app/src/main/res/values/strings.xml) | 投影仍以 `_id`、`title` 开头，追加 `modified`，让原来的点击、长按和标题读取继续使用对应行。适配器保留标题绑定，在下方用 `DateUtils` 把毫秒值格式化为本地日期和时间，精确到分钟。字段为 `NULL` 时显示 `—`。 |
| [NoteEditor.onPause / updateNote](../../app/src/main/java/com/example/android/notepad/NoteEditor.java) | `Save` 和系统返回统一由 `onPause` 保存，避免重复写入。先比较正文及本次传入的标题，只将有变化的字段和新的 `modified` 一起提交。新建空笔记退出时仍清理临时行，已有空正文仅查看时保留原行。撤销沿用原文恢复路径，保留当时已存的修改时间。 |
| [TitleEditor.onPause](../../app/src/main/java/com/example/android/notepad/TitleEditor.java) | 比较当前标题与查询得到的标题，发生变化时在同一次更新中写入 `title` 和 `modified`。正文和创建时间沿用原值。 |

## 设备实测

覆盖安装到 T01 的实验模拟器。A 是较早修改的 `Reading Notes`（ID 2），B 是 `Campus Plan`（ID 1）。使用原版界面入口操作，并通过 Provider 查询对照毫秒值。复测时以 `adb devices` 所列的实验模拟器序列号为准。

```powershell
adb -s emulator-5560 shell content query --uri content://com.google.provider.NotePad/notes --projection _id:title:note:created:modified
```

| 场景 | 操作与预期 | 实测 |
| --- | --- | --- |
| 历史笔记 | 升级后打开列表，预期两条笔记显示原有本地时间，B 在 A 前。 | 通过。B 显示 2:55 PM，A 显示 2:54 PM，两条的底层字段与 T01 一致。见图 1。 |
| 仅改正文，较早笔记上移 | 点开 A，在 `Reading Draft` 下加一行 `Read one chapter.` 后按 `Save`。预期时间更新且 A 排首行。 | 通过。A 的 `modified` 从 `1795244080042` 变为 `1795244621058`，显示 3:03 PM 并移至首行。标题、创建时间和 B 的记录保持原值。见图 2。 |
| 仅改标题 | 长按 B，选 `Edit title`，改为 `Campus Checklist` 并确认。预期只改标题也能更新修改时间、推进排序。 | 通过。B 的 `modified` 从 `1795244117739` 变为 `1795244643454`，显示 3:04 PM 并排到首行。其正文和创建时间保持原值。 |
| 只查看或原样保存 | 长按 A 选 `Open` 后返回，再点开 A 原样按 `Save`，随后从正文编辑器的更多菜单进入 `Edit title` 并原样确认。预期各操作都保留原时间。 | 通过。A 的 `modified` 始终为 `1795244621058`，两条的全部字段和排序均保持原值。 |
| 撤销正文改动 | 在 A 输入临时正文，从更多菜单选 `Revert changes`。预期恢复原文并保留原时间。 | 通过。A 回到已保存的两行正文，`modified` 仍为 `1795244621058`，两条的查询结果与操作前一致。 |
| 缺失时间 | 用 Provider 插入临时样本 `Legacy-T02`，正文为空，显式传入 `modified=NULL`。预期时间显示占位，只打开再返回时保留该行。 | 通过。列表显示 `—`，查看后仍为原空正文和 `NULL`，随后从长按菜单删除临时样本。 |
| 新建、空白退出与删除 | 新建空笔记直接返回，再建一条长标题的临时笔记并保存，最后长按删除。预期空笔记被清理，正常笔记显示标题与时间。 | 通过。空笔记退出后只剩原两条。新建样本的长标题及正文都与原版同样保存为完整文本，其 `created` 为 `1795244749940`，`modified` 为 `1795244755783`。删除后保留 A 和 B。 |

复制笔记后从列表选 `Paste` 的回归检查复现了旧问题。原版 `6a6d598` 与 T02 在同一设备上都打开了空编辑器，系统日志显示 `ClipboardService` 在编辑器取得焦点前拒绝了剪贴板读取。两次测试都删除了各自的临时空笔记。
