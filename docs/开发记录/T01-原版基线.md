## 源码观察

| 环节 | 原版数据流 |
| --- | --- |
| 存储与 URI | [NotePad.Notes](../../app/src/main/java/com/example/android/notepad/NotePad.java) 定义集合 URI `content://com.google.provider.NotePad/notes`。尾部加行 ID 即为单条笔记 URI。[NotePadProvider](../../app/src/main/java/com/example/android/notepad/NotePadProvider.java) 在 SQLite `note_pad.db` 的 `notes` 表中保存 `_id`、`title`、`note`、`created`、`modified`。两个时间字段为 Unix 毫秒整数。 |
| 新建 | [NotesList](../../app/src/main/java/com/example/android/notepad/NotesList.java) 从 `New note` 发出带集合 URI 的 `ACTION_INSERT`。[NoteEditor.onCreate](../../app/src/main/java/com/example/android/notepad/NoteEditor.java) 通过 `ContentResolver.insert` 取得单条 URI，再查 `_id`、`title`、`note`。Provider 在插入时补齐缺省的创建时间、修改时间、默认标题和空正文。 |
| 重开与改正文 | 点列表行时，`onListItemClick` 按真实行 ID 拼接单条 URI，发出 `ACTION_EDIT`。编辑器在 `onResume` 重查并显示正文，保存一份原文供撤销。`Save` 会调用 `updateNote` 再退出，返回也会从 `onPause` 保存。`updateNote` 写正文及当前 `modified` 并保留 `created`。新建时从正文生成初始标题，显式保存时最多取前 30 个字符并尝试在空格处截断，直接返回时会传入整段正文作为标题。 |
| 改标题 | 长按某行选 `Edit title` 时，菜单按所选 ID 把单条 URI 交给 [TitleEditor](../../app/src/main/java/com/example/android/notepad/TitleEditor.java)。它查 `_id` 和 `title`，点击 `OK` 结束 Activity，在 `onPause` 通过 Resolver 只写标题。正文编辑器的更多菜单也为已保存笔记提供 `Edit title`。 |
| 撤销与删除 | 编辑器菜单在输入与库中正文有差异时显示 `Revert changes`。`cancelNote` 在编辑旧笔记时写回进入编辑器时保存的正文，新建状态则删掉临时行。编辑器结束时如果正文为空，`onPause` 也会删除该行。列表长按删除按选中行 ID 调用 `delete`。 |
| 回到列表 | Provider 查询将传入的 `selectionArgs` 交给 SQLite，为游标设置通知 URI，并在写入后通过 `notifyChange` 通知变动。`NotesList.onCreate` 用 Activity 管理的游标查询 `_id` 和 `title`，排序为 `modified DESC`，`SimpleCursorAdapter` 将标题绑定到[单行布局](../../app/src/main/res/layout/noteslist_item.xml)的 `android.R.id.text1`。 |
| 原菜单与文本接口 | 列表提供 `New note`，剪贴板有内容时可用 `Paste`。长按菜单有 `Open`、`Copy`、`Delete` 及动态加入的 `Edit title`。正文编辑器有 `Save`、`Delete` 和按状态显示的菜单项。Provider 的 `getStreamTypes` 为单条 URI 声明 `text/plain`，`openTypedAssetFile` 通过管道让 `writeDataToPipe` 用 UTF-8 依次写标题、空行和正文，每次写入均以换行结尾。 |

## 设备实测

从实验模拟器空库开始，用 ADB 点按、长按及输入操作原版界面，并用 UIAutomator 读取屏幕节点。涉及时间字段时，通过下列只读命令核对 Provider 返回的值。复测时以 `adb devices` 所列的实验模拟器序列号为准。

```powershell
adb -s emulator-5560 shell content query --uri content://com.google.provider.NotePad/notes --projection _id:title:note:created:modified
```

| 场景 | 操作与预期 | 实际观察与结论 |
| --- | --- | --- |
| 新建、显式保存与返回保存 | 用 `New note` 创建 `Campus Plan` 后点 `Save`。再新建 `Reading Draft` 并按返回。预期两条都出现在列表。 | 通过。第一条保存前是 ID 1 的空白行，保存后标题和正文均为 `Campus Plan`。第二条返回后以 ID 2 保存，居列表首行。 |
| 改标题与重开 | 长按 `Reading Draft` → `Edit title`，改为 `Reading Notes` 并点 `OK`，再长按 → `Open`。预期新标题出现，原正文可读。 | 通过。列表及编辑器标题更新，正文仍为 `Reading Draft`。只改标题前后的 `modified` 均为 `1795244026825`。重开正文后直接返回，正文未变，`modified` 更新至 `1795244080042`。 |
| 编辑旧笔记并重排 | 点开当时在第二行的 `Campus Plan`，新增第二行 `Bring a notebook.` 后保存，再打开核对。预期正文保留且该笔记排到首行。 | 通过。两行正文可见，`created` 保持 `1795243996536`，`modified` 从 `1795244014991` 增至 `1795244117739`。列表首行为 `Campus Plan`，每行只显示标题。 |
| 撤销 | 重开 `Campus Plan`，记录原文，输入 `Unsaved` 后从更多菜单选 `Revert changes`。预期退出编辑器并保留原文。 | 通过。未改动时菜单隐藏撤销项，输入后出现。撤销返回列表，两条记录的正文和时间字段均与操作前一致。 |
| 删除临时笔记 | 保存 `Temporary Note`，长按该行 → `Delete`。另新建空笔记直接返回。预期两次操作后都只保留演示笔记。 | 通过。长按删除后仅 ID 3 的临时笔记消失，空白新建行在退出时被移除，两条演示笔记保留。 |
| 重启应用 | 停止应用进程后，从启动入口重开。预期两条样例可继续使用。 | 通过。列表按 `Campus Plan`、`Reading Notes` 排列，Provider 查询结果与重启前一致。 |

演示数据留在 `NotePad_Lab`，可在 Android Studio 的 Device Manager 启动该设备继续使用。复制和粘贴的入口已查源码，本次未做设备上的往返操作。

## 现有自动化测试

应用包和测试包通过 `gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest` 构建。安装至同一 AVD 后，在录入演示笔记前执行现有 JUnit 3 仪器测试。

```powershell
adb -s emulator-5560 shell am instrument -w -r -e class 'com.example.android.notepad.NotePadProviderTest,com.example.android.notepad.NotePadActivityTest' 'com.example.android.notepad.tests/android.test.InstrumentationTestRunner'
```

| 测试类 | 实际覆盖 | 结果 |
| --- | --- | --- |
| [NotePadProviderTest](../../app/src/androidTest/java/com/example/android/notepad/NotePadProviderTest.java) | 在测试库检查 URI/MIME 类型、流类型、可用的文本描述符和不支持的打开方式、文本管道返回的标题与正文、集合及单条查询（含投影和筛选参数）、插入、删除和更新。 | 9 项通过 |
| [NotePadActivityTest](../../app/src/androidTest/java/com/example/android/notepad/NotePadActivityTest.java) | 检查列表 Activity 能启动并得到实例。增删改等交互由上面的设备操作验证。 | 1 项通过 |
